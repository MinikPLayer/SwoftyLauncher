# 1.6.2

Swofty Launcher for F1 25 1.6.2 adds an optional way to start modded sessions on Linux without copying files into the game folder.

## Linux

- Add `--use-overlayfs` to the Steam launch option, after `run`, and the game runs from an OverlayFS mount: `<install folder>/bin/swofty run --use-overlayfs -- %command%`. The profile's files, the loader and the offline play stub are laid over the game folder in a private mount, so nothing is copied into it, backed up or rolled back. A launch with nothing changed starts in under a second, and exit takes no rollback time. Without the flag, sessions work as before.
- The game's logs and addon data go to `$DATA/profiles/<profile>/writes/`. The logs are also copied to `$DATA/logs/` and the session's folder.
- When OverlayFS can't be used (Flatpak Steam, no user namespaces, an EA app copy, a `swofty apply` install in the folder), a dialog asks whether to launch by copying files or to cancel. **Don't show again** with **Continue** skips it next time. The launcher shows a note for the last fallback.
- `swofty doctor` shows whether the launch option has the flag and whether a test mount works.
- The Career Editor works in an OverlayFS session: the launcher reaches the game's addon folder through the game's mount, and shows the last snapshot from the profile's upper dir when the game is closed. Rebuild the Career Editor's launcher helper from this version's source for it to work.
- Addon authors: `addon_game_dir` can now be a path under `/proc/<pid>/root/…` while the game runs, or the profile's upper dir when it doesn't. Ask for it every time you use it. See [`addon_game_dir`](/reference/addons/launcher-api/host-calls#addon-game-dir).

See [Linux and Steam Deck](/guide/linux#optional-run-the-game-from-an-overlayfs-mount) and [OverlayFS sessions](/reference/launch#overlayfs-sessions).
